# 三国志战略版战报模拟器规格

## 目标

构建一套可解释、可调参、可扩展的回合制战报模拟器，用于把当前阵容静态评分升级为“模拟战报 + 批量胜率 + 战损稳定性”的综合分析。

一期目标：

- 支持双方三武将阵容输入。
- 支持准备阶段与最多 8 回合战斗流程。
- 支持基础行动顺序、速度/先攻、兵种适性、兵种克制、兵力衰减、增减伤、控制、治疗。
- 支持单场固定 seed 战报复现。
- 支持多次模拟输出胜率、平均剩余兵力、战损比、稳定性指标。
- 输出明确的模拟假设，避免把估算结果误解为官方精确战报。

## 非目标

- 一期不追求 100% 复刻官方隐藏算法。
- 一期不覆盖全量战法的所有特殊交互。
- 一期不替换现有静态评分总分，只并列输出模拟评分建议。
- 一期不做后台运营页，先保证服务端 API 与前端对位页可用。

## 输入模型

模拟 API 接收：

```js
{
  own: {
    troop: "枪兵",
    generalIds: ["...", "...", "..."],
    tacticIds: ["...", "...", "..."],
    redLevels: [0, 0, 0],
    troops: [10000, 10000, 10000]
  },
  enemy: {
    troop: "骑兵",
    generalIds: ["...", "...", "..."],
    tacticIds: ["...", "...", "..."],
    redLevels: [0, 0, 0],
    troops: [10000, 10000, 10000]
  },
  seed: 20260616,
  iterations: 1,
  options: {
    maxRounds: 8
  }
}
```

`generalIds` 和 `tacticIds` 复用现有资料库 ID；当调用方传入对象时，也允许直接使用对象，以便测试和后续扩展。

单场模拟返回：

```js
{
  summary: {
    winner: "own",
    result: "win",

    ownRemaining: 12840,

    ownDamage: 18210,

    enemyHealing: 900,

    enemyControlTurns: 1,

```

批量模拟返回：

```js
{

  aggregate: {
    averageOwnRemaining: 8200,
    averageEnemyRemaining: 5200,
    averageTroopLossRatio: 0.64,
    stability: "中高"
  },
  samples: [],
  assumptions: []
}
```

## 战斗流程

1. 归一化双方阵容，查找武将、战法、兵种适性和基础属性。
2. 创建初始状态：双方队伍、武将兵力、最大兵力、属性、状态、统计指标。
3. 准备阶段按顺序执行：被动 → 阵法 → 兵种 → 指挥。
4. 每回合执行：主动 → 普攻 → 突击。
5. 每个行动阶段内：先攻优先；无先攻按速度降序；同速按稳定顺序。
6. 每次行动后检查是否有一方全灭。
7. 最多执行 8 回合；未分胜负按剩余总兵力判定，差距很小时判为平局。

## 状态系统

状态分为：

- 增益：增伤、减伤、先攻、属性提升、抵御。
- 减益：易伤、属性降低。
- 控制：缴械、计穷、震慑、虚弱、混乱、禁疗。
- 持续：持续伤害、休整/急救。

叠加规则：

- 同类百分比增益默认取较高值并刷新持续回合。
- 控制状态默认不叠层，只刷新剩余回合。
- 不同来源但同类效果一期不做复杂优先级，统一记录假设。

## 伤害与治疗公式

一期采用可调近似公式：

```js
damage = baseRate
  * attributeFactor
  * troopAptitudeFactor
  * troopCounterFactor
  * troopStrengthFactor
  * damageBonusFactor
  * damageReductionFactor
  * randomFactor
```

默认取值：

- `baseRate`：普攻或战法伤害率。
- `attributeFactor`：攻击方武力/智力与防守方统率/智力差异。
- `troopAptitudeFactor`：S/A/B/C 适性乘数。
- `troopCounterFactor`：克制 1.12，被克 0.9，无克制 1。
- `troopStrengthFactor`：当前兵力占最大兵力的衰减系数。
- `randomFactor`：固定 seed 下的 0.9 到 1.1 浮动。

治疗公式与伤害公式类似，基于治疗者智力、治疗率、当前兵力衰减和随机浮动。

## 战法支持范围

一期采用“显式规则 + 通用 fallback”：

显式规则优先覆盖：

- 盛气凌敌：准备阶段对敌方前两名施加缴械。
- 横扫千军：主动兵刃群攻，目标被缴械时追加震慑概率。
- 暂避其锋：准备阶段为低武力/低智力友军提供兵刃/谋略减伤。
- 草船借箭：主动净化并治疗友军。
- 太平道法：被动提高主动谋略战法发动和输出稳定性。
- 士别三日：前几回合规避/蓄势，后续谋略伤害。
- 当锋摧决：突击伤害并施加伪报/禁用估算控制。
- 刮骨疗毒：治疗最低兵力友军并净化。

通用 fallback：

- 根据战法类型与描述关键词识别输出、治疗、控制、减伤、增伤、先攻。
- 未识别出具体伤害率时使用默认估算值，并在 `assumptions` 中标注。

## 评分联动

现有 `analyzeLineup(input)` 保持静态评分不变。新增可选模拟结果字段：

- `simulationStats.winRate`
- `simulationStats.averageRemaining`
- `simulationStats.averageTroopLossRatio`
- `simulationStats.stability`
- `simulationStats.scoreSuggestion`

一期只并列展示，不覆盖原总分。

## API 约定

新增：

- `POST /api/v1/battles/simulate`

请求：`{ own, enemy, seed, iterations, options }`

响应：

```js
{ ok: true, data: { summary, rounds, metrics, aggregate, samples, assumptions } }
```

错误：

- 缺少双方阵容：400。
- 武将不足：400。
- `iterations` 超出上限：400。

## 边界情况

- 武将不足 3 人时拒绝模拟。
- 战法不足时允许模拟，但在 assumptions 中标注。
- 兵力缺省时按每人 10000。
- 阵容同一武将重复时拒绝模拟。
- 无法识别的战法不报错，走普通估算或忽略，并写入 assumptions。
- 批量模拟默认最多 200 次，避免接口被一次请求拖垮。

## 验证标准

- 固定 seed 的战报结果完全一致。
- 战斗最多 8 回合。
- 先攻武将先于高速度但无先攻武将行动。
- 兵种克制会改变伤害结果。
- 治疗、控制、伤害会进入 metrics。
- `POST /api/v1/battles/simulate` 返回结构稳定。
- 前端对位页能展示模拟摘要与回合日志。

## 持续开发阶段

P7 目标是在 MVP 基础上提高机制可信度和解释能力，仍坚持“近似 + 可调参 + 可解释”，不伪装成官方隐藏算法。

### 机制扩展

新增或深化以下状态：

- 连击：允许普攻阶段追加一次普通攻击，并触发突击判定。
- 规避：在伤害结算前概率或次数抵消伤害。
- 洞察：免疫或抵消缴械、计穷、震慑、混乱等控制。
- 抵御：抵消下一次伤害。
- 会心/奇谋：兵刃/谋略伤害触发额外倍率。
- 急救/休整：按行动或回合进行治疗。
- 灼烧/叛逃等持续伤害：在回合开始或结束结算。

回合流程扩展为：回合开始 → 主动 → 普攻 → 突击 → 回合结束。指挥、被动、阵法、兵种效果按描述映射到准备阶段或回合钩子。

### 战法规则扩展

战法支持从“少量显式规则 + fallback”升级为“规则注册表 + 批次补全”：

- 解析辅助：发动率、伤害率、目标数、持续回合、准备一回合、控制关键词。
- 显式规则优先覆盖机制型战法，例如连击、洞察、规避、抵御、持续伤害、休整/急救、常见阵法/指挥。
- 每条未精确覆盖的特殊效果必须写入 `assumptions`，并在 `ruleCoverage` 中体现 fallback 比例。

### 阵容输入扩展

在保持旧输入兼容的前提下，阵容可选支持：

```js
{
  attributePoints: [{ force: 20, intelligence: 0, command: 0, speed: 0 }],
  equipment: [{ name: "援助甲", effect: "援护" }],
  bondEnabled: true,
  battleOptions: { terrain: "默认", morale: 100 }
}
```

`attributePoints` 直接修正武将属性；`equipment` 优先按明确字段生效，否则按关键词估算；`bondEnabled` 根据资料库 `bonds` 匹配同队缘分并输出增益或假设。

### 报告解释扩展

模拟报告追加：

- `highlights`：最高伤害、最高治疗、关键控制、关键战法、主要假设。
- `ruleCoverage`：显式规则命中、fallback 次数、估算比例。
- `distribution`：批量模拟的最佳样本、最差样本、胜率稳定性原因。
- `metrics` 扩展：规避、抵御、会心、奇谋、持续伤害、状态命中次数。

### 前端展示扩展

对位页模拟弹窗支持：

- 设置模拟场次、最大回合、固定 seed 或随机 seed。
- 展示全部 assumptions，并可折叠。
- 展示 highlights、ruleCoverage、稳定性原因和关键样本。
- 回合日志按阶段折叠，避免长日志影响阅读。
- local 模式明确提示切换远程 API，而不是静默失败。

### 部署验收

完成 P7 后执行：

- `npm test`
- `npm --prefix src run build:h5`
- `npm --prefix admin run build`
- 临时 HTTP 服务请求 `POST /api/v1/battles/simulate`
- 部署到服务器并通过 `sz.qihangwk.com` 验证页面效果和 `/health`。

## P8：赛季资料与规则更新系统

P8 目标是在 P7 模拟器基础上建立可持续更新流水线，让每个赛季新增武将、战法、兵种战法和装备后，都能先导入草稿、审核差异、发布版本，再用于战报模拟。系统仍不声称复刻官方隐藏公式，所有未显式覆盖的战法必须通过覆盖状态、假设说明和待办列表透明呈现。

### 核心对象

- `season`：赛季或剧本标识，例如 `s1`、`s2`、`pk`，用于按赛季查找最新发布资料。
- `catalogVersionId`：资料版本 ID，用于锁定一次模拟使用的完整资料快照。
- `catalog snapshot`：完整资料快照，包含 `meta`、`generals`、`tactics`、`troopTactics`、`equipment`。
- `catalog diff`：新旧版本对比结果，按资料类型输出 `added`、`changed`、`removed`、`unchanged`。
- `tactic rule todo`：战法规则待补任务，记录覆盖状态、优先级、状态和备注。

### 资料版本与发布约束

- `data/catalog.json` 保留为静态基线，不由后台发布流程直接覆盖。
- 导入资料先生成 `draft` 版本和导入任务，不影响线上已发布版本。
- 发布 `draft` 时，同一赛季旧 `published` 版本置为 `archived`。
- 丢弃 `draft` 只改变草稿和导入任务状态，不删除静态基线或线上版本。
- 导入失败、校验失败或发布失败不得影响当前模拟接口默认资料。
- 资料快照需要记录 hash、数量统计、来源、导入时间、发布时间和操作者。

### 差异审核

差异计算覆盖：

- 武将：`generals`
- 战法：`tactics`
- 兵种战法：`troopTactics`
- 装备：`equipment`

对比时忽略 `generatedAt`、`updatedAt`、`fetchedAt` 等拉取时间字段，避免每次导入都误判为全量变更。差异明细应至少包含资料 ID、名称、变更类型和前后关键字段。

### 模拟接口版本选择

`POST /api/v1/battles/simulate` 支持：

```js
{
  season: "pk",
  catalogVersionId: "...",
  options: {
    season: "pk",
    catalogVersionId: "..."
  }
}
```

优先级：`catalogVersionId` > `options.catalogVersionId` > `season` > `options.season` > 默认静态资料。

不传 season/version 时，旧行为保持不变；指定不存在版本时返回稳定错误，不静默降级到默认资料。

### 输出扩展

单场和批量模拟报告新增：

- `catalogContext`：本次使用的资料来源、赛季、版本、状态和版本标识。
- `ruleCoverage.coverageByTactic`：战法级覆盖明细，包含战法 ID、名称、类型、覆盖状态、说明和是否存在待办。
- 保留旧字段：`explicit`、`fallback`、`estimated`、`missed`、`explicitTactics`、`fallbackTactics`、`missedTactics`、`explicitRate`、`estimatedRate`。

### 战法覆盖分类

- `explicit`：命中显式规则注册表。
- `fallback`：命中通用估算关键词，可参与模拟但可信度低于显式规则。
- `missed`：无法识别机制，仅记录假设或忽略，不应被用户误认为精确模拟。
- `manual/ignored`：管理员人工标记的非优先补全项。

发布资料版本后，系统遍历 `tactics + troopTactics`：

- 对 `missed` 自动生成规则待办。
- 对 `fallback` 展示估算状态，允许人工创建低优先级待办。
- 已存在相同战法待办时不重复创建。

### 管理端能力

后台新增“赛季资料”页面：

- 版本列表：查看赛季、版本、状态、来源、数量、发布时间。
- 导入审核：粘贴或上传 JSON 快照，生成草稿和 diff，支持发布/丢弃。
- 规则覆盖：查看全量战法覆盖状态，创建或更新规则待办。

所有管理接口沿用 `x-admin-token`，发布和丢弃写入审计日志。

### 用户端能力

对位页模拟弹窗在远程模式下拉取资料版本列表，支持选择赛季或资料版本。模拟结果展示本次使用的资料版本、战法级覆盖明细；当估算率较高或存在未覆盖战法时，继续提示“仅用于方向判断”。

### P8 验收标准

- 可以创建 catalog 版本草稿并查看 diff。
- 可以发布/丢弃资料版本，公共 API 能按 season/version 读取。
- 战报模拟可按 season/version 解析资料，并返回 `catalogContext`。
- 后台能查看战法规则覆盖状态和待办。
- 用户端模拟弹窗可选择赛季并展示版本和战法覆盖明细。
- `npm test`、H5 构建、admin 构建通过。
- 部署到 `sz.qihangwk.com` 后，线上 health、前台、后台、catalog versions 和模拟接口冒烟通过。

## P9：官方公开资料自动采集、入口视觉统一与评分增强

P9 目标是在 P8 的资料版本审核链路上增加官方公开资料自动采集能力，并把用户端的核心模拟入口、底部 tab 视觉和评分解释提升到可运营状态。系统只采集公开可访问资料，不绕过登录、验证码、反爬或权限限制；采集结果只生成草稿，必须人工审核 diff 后才允许发布。

### 公开资料采集边界

- 采集来源限定为公开可访问的官方资料接口或页面。
- 不采集非公开数据，不保存官方图片素材，不绕过访问控制、验证码或反爬限制。
- 采集频率必须保守，默认不开启高频轮询。
- 采集失败不得影响服务启动、当前已发布资料或默认静态资料。
- 自动采集不得直接覆盖 `data/catalog.json`、`data/catalog.js` 或线上 `published` 版本。

### 采集草稿链路

官方公开资料采集复用 P8 导入审核模型：

1. 管理端或定时任务触发采集。
2. 服务端拉取公开资料并 normalize 为 catalog snapshot。
3. 系统按当前赛季 published 版本或静态基线计算 diff 和 snapshot hash。
4. 如果无有效变化，返回 `skipped` 结果，不生成重复草稿。
5. 如果存在变化，创建 `source: "official"` 的 `draft` 资料版本和导入任务。
6. 管理员在后台查看 diff 后选择发布或丢弃。

导入任务返回字段应包含：

```js
{
  ok: true,
  skipped: false,
  job: { id, status: "draft", source: "official" },
  version: { id, seasonKey, versionKey, status: "draft", counts, snapshotHash },
  diff: { summary, generals, tactics, troopTactics, equipment }
}
```

无差异时返回：

```js
{
  ok: true,
  skipped: true,
  reason: "官方公开资料与当前基线无差异。",
  counts: {}
}
```

### 定时策略

- 使用 Node 内置 `setInterval`，不新增调度依赖。
- 通过环境变量控制是否启用、间隔小时、默认赛季标识和版本前缀。
- 服务启动失败不应由采集任务导致；采集任务错误只记录运行状态和审计日志。
- `app.stop()` 必须清理定时器，避免测试和重启时挂住进程。
- 定时采集与手动采集使用同一套草稿创建逻辑，保证行为一致。

### 后台能力

后台“赛季资料”页面在现有导入审核能力上扩展：

- 提供“立即采集官方公开资料”按钮。
- 展示采集中状态、最近采集结果、无差异跳过、错误摘要。
- 采集成功后刷新导入任务、版本列表和 diff 明细。
- 明确提示采集结果仍是草稿，需要人工发布才会影响线上模拟。
- 发布、丢弃和规则覆盖能力继续复用 P8 页面，不新增独立管理页。

### 用户端入口与 tab 统一

- 对位页“战报模拟”入口必须从普通底部按钮升级为更明显的主功能入口。

## P11：主动准备战法、发动概率与兵书跳过准备

P11 目标是修正主动准备战法的释放时机：发动判定成功后不能默认当回合直接生效，而应按战法描述进入 1 回合或 2 回合准备；命中兵书或配置的跳过/减少准备效果时，才允许提前释放。该机制仍属于可解释估算，不声称完全复刻官方隐藏算法。

### 主动准备与概率规则

- `主动` 和兼容的行动型 `自带` 战法在每次主动阶段先判定发动概率。
- 发动概率优先解析描述中的 `X%概率`；未提供时沿用类型默认估算概率。
- 发动失败时不进入准备队列、不释放效果，并在回合日志记录 `未发动`。
- 发动成功后解析 `prepareRounds` / `prepareTurns` / `prepareRound`，或从描述中解析“准备1回合、准备一回合、准备2回合、准备两回合”等文本。
- 未命中明确回合数但包含“准备”关键词时，默认按 1 回合准备估算。
- 准备完成释放时不再次判定发动概率；概率已经在进入准备前结算。

### Pending 准备队列

主动准备战法进入武将自己的 `pendingPrepareTactics` 队列：

```js
{
  tacticKey,
  tactic,
  remaining,
  prepareRounds,
  startedRound,
  startedPhase
}
```

释放时机：

- 1 回合准备：开始准备的当回合不生效，下一次该武将主动阶段释放。
- 2 回合准备：中间主动阶段记录 `准备中`，第三次主动阶段释放。
- 同一战法 pending 期间不重复入队，避免同一武将同一战法多段重叠释放。
- 武将死亡、`disabledTactics`、`计穷`、`震慑` 等阻止主动战法时，pending 准备被取消并记录原因。

### 跳过准备与减少准备输入

阵容归一化支持以下字段作为准备修正来源：

- `lineup.prepareModifiers`
- `lineup.battleBooks`
- `lineup.books`
- `general.prepareModifiers`
- `general.battleBooks`
- `general.books`

归一化为：

```js
{
  reducePrepareTurns: 0,
  skipPrepareChance: 0,
  sources: []
}
```

结构化字段支持 `reducePrepareTurns`、`reducePrepareRounds`、`prepareReduction`、`skipPrepareChance`、`skipPrepareProbability`、`skipChance`。文本估算支持“跳过准备”“无需准备”“免除准备”“X%概率跳过准备”“减少/缩短 X 回合准备”等关键词。命中估算后会写入 `assumptions`，提示来源是兵书或配置估算。

### 战报日志

P11 新增或明确以下 action 类型：

- `未发动`：本次发动率判定失败。
- `开始准备`：发动成功并进入准备队列。
- `准备中`：尚未达到释放时机。
- `准备完成`：准备结束并释放战法效果。
- `跳过准备`：兵书或配置使本次准备回合归零。
- `准备取消`：准备完成前被控制、禁用或死亡打断。

### 估算边界

- 当前只模拟基础的发动率、准备回合、跳过/减少准备和控制打断，不覆盖所有战法专属例外。
- 兵书文本和配置字段按关键词估算，实际官方优先级、叠加规则和隐藏判定仍需后续通过规则库逐条补全。
- `突击` 战法仍按普攻后即时判定释放，不进入主动准备队列。

### P11 验收标准

- 准备 1 回合主动战法当回合只记录 `开始准备`，不释放战法伤害或治疗。
- 准备 1 回合战法在下一次主动阶段记录 `准备完成` 并释放。
- 准备 2 回合战法会先记录 `准备中`，再在正确主动阶段释放。
- `0%概率` 战法只记录 `未发动`，不进入准备队列。
- `skipPrepareChance: 1` 或等价兵书文本能记录 `跳过准备` 并当回合释放。
- 准备完成前受到 `计穷`、`震慑` 或战法禁用时记录 `准备取消`，不释放 pending 战法。



## P12：被动、指挥、阵法、兵种战法机制补强

P12 继续补齐主动准备战法之外的非主动类战法。资料来源仍以数据库 published catalog snapshot 为主，模拟器根据战法 `type`、公开描述和已登记显式规则决定生效时机。

### 类型与时机

- 被动：优先视为战斗开始即生效的自身常驻或条件触发效果，可注册全程状态、属性修正、连击、洞察、抵御、规避、会心、奇谋、急救或持续恢复。
- 指挥：准备阶段稳定生效，默认不走主动战法发动概率；可对友军或敌军施加队伍级增减伤、治疗、控制、先攻、洞察或持续状态。
- 阵法：准备阶段按队伍或位置生效，优先表现为队伍光环、属性修正、伤害修正或受伤修正。
- 兵种：必须满足当前队伍兵种或描述中的兵种条件后才生效；真实资料中 `type` 可能直接是 `骑兵`、`盾兵`、`弓兵`、`枪兵`、`器械`，模拟器按兵种战法处理；不匹配时不得静默套用效果。
- 回合钩子：公开描述中属于回合开始、回合结束、持续伤害、持续治疗的效果，复用状态系统在对应阶段结算。

### 覆盖与估算边界

- 显式规则命中的战法标记为 `explicit`，并在 `coverageByTactic` 中展示规则来源。
- 未写专属规则但命中类型感知关键词的战法标记为 `fallback`，说明结果用于方向判断。
- 未命中显式规则和通用估算的战法标记为 `missed`，提示需要继续补充战法规则。
- 官方隐藏目标选择权重、内部优先级、未公开随机逻辑和精确伤害公式不宣称完全复刻；无法从公开资料解析的数值使用保守默认值，并写入 `assumptions`。

### P12 验收标准

- 被动、指挥、阵法、兵种至少可按公开资料拆为常驻、队伍光环、兵种限定、回合触发和准备阶段效果。
- 代表性被动、指挥、阵法、兵种战法有测试覆盖，日志能展示来源和触发阶段。
- 兵种条件不匹配时不会错误生效，并记录可解释假设。
- `ruleCoverage.coverageByTactic` 与前台模拟结果能展示 explicit、fallback、missed。
- 本地测试、构建、部署和线上冒烟通过。

## P13 规则库显式覆盖补强

P13 继续沿用数据库 published catalog snapshot 作为生产资料来源，不改变战斗主流程和版本发布流程。新增规则集中在 `utils/simulator/tactics.js` 的显式规则表中，目标是把公开文案稳定、影响评分较大的战法从 fallback/missed 推进到 explicit。

新增覆盖包括：

- 指挥/阵法：`八门金锁阵`、`抚辑军民`、`御敌屏障` 在准备阶段稳定生效，分别按先攻、敌方输出压制、我方减伤和休整近似处理。
- 兵种战法：`藤甲兵`、`陷阵营`、`白马义从`、`虎豹骑`、`青州兵` 必须满足队伍兵种要求才生效；不匹配时跳过效果并写入 assumptions。
- 主动战法：`破阵摧坚`、`杯蛇鬼车`、`所向披靡`、`据水断桥` 覆盖群体兵刃/谋略伤害、属性削弱近似、治疗和虚弱控制；准备战法仍走 pending 准备队列。
- 突击战法：`暴戾无仁`、`速乘其利`、`弯弓饮羽` 只在普通攻击后的突击阶段触发，按伤害加混乱/计穷/缴械近似处理。

仍无法公开精确还原的隐藏参数、目标权重、属性降低公式、延迟结算和发动率修正继续写入 assumptions，避免把估算结果误标为官方完整算法。

## P14 高影响战法显式覆盖继续补强
